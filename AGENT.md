# AGENT.md — working guide for AI agents on this codebase

A browser port of Mini Militia Classic built from assets reverse-engineered out of
the official APK. Read `context.md` first for how the assets were obtained and what
the binary formats are. This file tells you how to work on the code without
re-breaking things.

## Golden rules

1. **Never trust raw `requestAnimationFrame` timestamps.** dt must be
   `clamp((t - lastT)/1000 || 0.016, 0.001, 0.033)`. A negative dt once caused an
   infinite loop in `Soldier.physics` (the collision walk marched *away* from its
   target forever) — this is a real browser scenario (tab switches), not just a
   test artifact. Tripwire guards (`TRIP(...)`) exist in the hot loops; keep them.
2. **TMX object y-coordinates are stored bottom-up** (cocos convention with a
   double flip — the original authors generated maps programmatically).
   `GameMap` flips them once at load: `y: this.h - o.y`. Tile layer data is NOT
   flipped. Do not "fix" either of these; palms-on-the-ground and
   spawns-on-platforms depend on this exact combination.
3. **Spawn points can sit inside floating geometry** (Outpost has cave ceilings).
   `Soldier.respawn()` de-embeds by walking up; `physics()` has a runtime unstick
   safety net. Preserve both.
4. Everything here is for **personal/educational use** — the assets are
   © Appsomniacs/Miniclip. Never add anything that publishes/redistributes them.

## Architecture (2-minute tour)

```
index.html        loader → lobby (map picker + solo/host/join) → canvas game
js/main.js        ALL game logic (~1200 lines): Soldier, matter.js wiring, weapons fire,
                  bullets/nades/particles, bots, pickups, camera, HUD, net glue
js/vendor/matter.min.js  matter-js 0.20.0 (MIT) — collision resolution world
js/map.js         GameMap (TMX-JSON render + tile collision + solid-rect meshing
                  for matter) & Atlas (cocos plist, anchored drawA)
js/weapons.js     WEAPONS + NADES dicts — keys are the TMX pickup `weapon` ids
js/audio.js       Sfx: WebAudio, wav bank, loops (jet/flame)
js/net.js         Net (ws client) + snapshot/input codecs
server/server.js  ws relay: rooms keyed by map name, first joiner = host,
                  host promotion on disconnect, port auto-fall-forward
test/             headless harness (browser stubs) + solo & e2e tests
data/ | img/ | audio/   generated by ../mm_analysis/pipeline/extract.py — do not hand-edit
```

### Physics (matter.js, since 2026-09)
`initPhysics()` builds a static world from `GameMap.solidRects()` (greedy-merged
tile rectangles) plus boundary walls (bottom intentionally open — the void death
line at y > map.h+300 catches fallers; do NOT add a floor there). Soldiers hold
matter bodies (inertia ∞, collision category 0x2 — they pass through each other
and nades); grenades are circles (0x4). Gravity/accel/jet are integrated by game
code and handed over as per-step velocities (`Body.setVelocity({x: vx*dt,
y: vy*dt})`, `Engine.update(engine, 1000/60)`) — so the legacy movement feel is
preserved exactly and matter only resolves collisions. Direct `x/y` teleports
must also `Body.setPosition`. Bullets stay custom (raycast steps), ghosts have
no bodies. Harness loads the vendor file first (UMD needs non-module scope).

### Netcode model (host-authoritative)
- **Host** runs the full sim. Remote players are real `Soldier`s whose input
  comes from `remoteInput` (set from guest `inp` packets, 30 Hz).
- **Host → guests:** 20 Hz `snap` (packed rows: id,x,y,aim,hp,dead,wep,ammo,fuel,
  facing) + immediate events (`fire`, `nade`, `boom`, `death`, `pk`, `sfx`).
  Guests render remote soldiers from snapshots; guest-side bullets/nades are
  **visual only** (`ghost: true`, never damage).
- **Guests** simulate only their own soldier locally for responsiveness and get
  position-corrected (lerp, hard snap if > 220 px) + authoritative hp/weapon/ammo.
- Guests fire *through* the host: input travels up, host spawns the real bullet
  and echoes a `fire` event back so the shooter sees their own tracer.
- Late joiners retry `hello` every second until the host acks with `pkinit`
  (pickup state). The host also self-heals a lost `pjoin` by upserting the
  player on its first `inp`/`hello` — both sides survive the join race where
  messages arrive before the peer's handlers are installed.

## Commands

```bash
cd ~/mm_web
node test/solo_test.js     # headless solo sim (2 maps, combat, touch, deaths)
node test/e2e_test.js      # REAL server + host + guest over WebSockets (13 checks)
node server/server.js      # relay on 8090, falls forward to 8091+ if busy
python3 -m http.server 8080
```

**Run both tests before declaring any change to main.js/net.js/server.js done.**
They are the only safety net (no browser in Termux). The e2e test spawns a real
child-process guest — if you change the protocol, update `guest_child.js` too.

## Rebuilding assets from the APK

```bash
python3 ~/mm_analysis/pipeline/extract.py    # re-extracts everything into ~/mm_web
```
Sources: `~/mm_analysis/apktool_out/assets` (apktool output of the original APK).
The pipeline carves 111 wavs out of `da2sound16.ckb`, converts all TMX → JSON,
converts both atlas plists → JSON, copies spritesheets. New maps added to the APK
appear automatically; wire them into the `MAPS` list in `js/main.js`.

## Adding things (where they go)

- **New weapon:** entry in `WEAPONS` (key MUST match the TMX pickup id), sprite
  must exist in `data/atlas/menuTexture.json` (check with python/jq). Optional
  `sfx` — must be one of the carved names in `audio/`.
- **New map to the lobby:** add `["file", "Label"]` to `MAPS` in `js/main.js`.
  Nothing else — tilesets/backgrounds resolve by name.
- **New net message:** add to `setupHostNet`/`setupGuestNet` in main.js AND the
  e2e test. Keep it JSON; the relay is generic (`c2c` pass-through).
- **New sound trigger:** `Sfx.play(name, vol, rate)` — name is the wav basename.

## Known sharp edges

- `Atlas.drawA` is the anchored (trim-aware, flippable) blit. Art orientation
  (pixel-verified): head + gun art face RIGHT naturally; leg + arm art face
  LEFT. So in `Soldier.draw()` the head and gun are never flipped (the outer
  facing mirror turns them), while legs/arms carry `flip=true`. Getting this
  wrong puts the face opposite to the barrel when facing left.
  `xE.png` = gun with mag removed (reload state), `xMag.png` = detached mag.
- `Atlas.draw` handles `rot` frames (90° stored rotated) — most frames aren't,
  but `check` any new frame you use.
- Deep links: `?solo=<map>[&demo][&flashhold][&colliders][&bots][&zoom=N]` skips the lobby (`demo`
  holds fire, `flashhold` pins the muzzle flash on — used by visual debugging, `colliders`
  draws matter.js bodies; runtime toggle: `` ` `` key, `bots` spawns the 2 practice bots).
- Guest own-death/respawn is snapshot-driven only: `die()` from the `snap`
  dead flag, resurrect from the alive flag; `physics()` deliberately does NOT
  auto-respawn guest-me (a local timer used to flap against the host's).
- Bots are opt-in in solo (`&bots` deep link / `startGame({bots:true})` /
  `__startSolo(map, true)`); the default solo game is just you. botThink stays
  covered by solo_test, which starts with bots enabled. In MP the host's
  `G.players` holds remotes instead.
  `Soldier.update()` must feed `botThink`'s `ai.input` into `physics()` — bots
  silently freeze if that wire is dropped (it happened once; solo_test's bot
  walk/aim/fire checks now guard it, with air-fall + overlap fallbacks because
  spawn geometry can wedge a bot against a wall).
- **Headless ≠ browser collision**: `GameMap.buildMask()` needs a real canvas
  (alpha-traced 2px mask). The harness has none, so tests run on whole-tile
  gid fallback — on 1outpost many pads sit inside invisible-solid gid-15 tiles
  that only the browser mask resolves as air. Tests that place bodies must
  verify the spot is free via `rectHitsWorld` in the headless model (e2e pickup
  probe picks a pad with a reachable free spot for this reason).
- Collider debug overlay: `` ` `` key or `?colliders` draws every matter body
  (terrain green, boundary purple, soldier orange, nade yellow) + HUD legend.
  Uses `ctx.measureText`-free layout — the harness ctx stub returns undefined
  for every method, so any new HUD text layout must not chain its result.
- `humanInput()` is shared by host-me and guest-me; bot AI never uses it.
- The harness `frames()` clock is monotonic (`lib._clock`) — a previous version
  reset it per call and *manufactured* the negative-dt bug. Don't regress it.
- Termux quirk: `kill %1` doesn't work in non-interactive shells — kill by PID,
  or you'll leak servers on ports (the fallback in server.js now masks this).
